# F1 Race Predictor — Engineering & Design Plan

**Project:** `f1-predictor`
**Target race:** 2026 United States Grand Prix — Round 18
**Circuit:** Circuit of the Americas (COTA), Austin, Texas — 5.513 km, 56 laps
**Race start:** 2026-10-25 20:00 UTC (15:00 local CDT) — *verified via OpenF1 session_key `11396`*

**Status:** Plan approved → ready for build

---

## 1. Objective

Build a Python prediction engine that forecasts the finishing order, win/podium/points probabilities, and race-time deltas for **today's Formula 1 race**, using three independent public data APIs. Ship a clean JSON contract plus a professional single-page dashboard that visualises the output.

### Success criteria

| # | Criterion | Measure |
|---|-----------|---------|
| 1 | Data completeness | ≥ 3 independent sources per driver (quali, race pace, form) |
| 2 | Reproducible | One command rebuilds the entire prediction from cache |
| 3 | Calibrated | Top-3 predicted drivers contain the actual winner (backtested on 2026 rounds 1–17) |
| 4 | Explainable | Every driver row carries a contribution breakdown, no black-box number |
| 5 | Degradable | Runs with any 1 of 3 APIs offline |

## 3. System Architecture

```
┌──────────────────────────────────────────────────────────────────────┐
│                         DATA LAYER (async, cached)                   │
│                                                                      │
│  FastF1  ──────►  telemetry · lap times · sectors · compounds        │
│                   fuel-corrected long-run pace · speed traps         │
│                                                                      │
│  OpenF1  ──────►  session results · positions · intervals · pits     │
│                   weather · race control · driver metadata           │
│                                                                      │
│  Jolpica ──────►  standings · 5-season results · circuit history     │
│                   schedule · grid→finish priors                      │
└───────────────────────────────┬──────────────────────────────────────┘
                                │  normalised to one DataFrame per driver
                                ▼
┌──────────────────────────────────────────────────────────────────────┐
│                      FEATURE ENGINEERING                             │
│  quali_pace · long_run_pace · deg_rate · team_form · driver_form     │
│  circuit_affinity · reliability · grid_position · strategy_prior     │
└───────────────────────────────┬──────────────────────────────────────┘
                                ▼
┌──────────────────────────────────────────────────────────────────────┐
│                     PREDICTION ENGINE (ensemble)                     │
│                                                                      │
│  ┌────────────────────────┐      ┌──────────────────────────────┐    │
│  │ Monte Carlo race sim   │ 60%  │ Gradient-boosted classifier  │    │
│  │ 20 000 lap-by-lap      │─────►│ grid + form → finish         │    │
│  │ runs, tyre/pit/SC/DNF  │      │ trained 2022–2026            │    │
│  └────────────────────────┘      └──────────────────────────────┘    │
│                    │                          │                      │
│                    └──────────┬───────────────┘                      │
│                               ▼                                      │
│              blend → temperature calibration → normalise             │
└───────────────────────────────┬──────────────────────────────────────┘
                                ▼
                     output/prediction.json  (UI contract)
                                ▼
                    Dashboard (HTML/CSS/JS, no build step)
```

### Why an ensemble, not a single model

A pure ML model cannot see today's tyre degradation. A pure simulation cannot learn "Antonelli converts poles at 78% this season". The simulation captures **physics of this weekend**; the classifier captures **behavioural priors across seasons**. Blending cuts variance on both sides.

### 4.3 Fallback chain (graceful degradation)

```
qualifying classification:  OpenF1 session_result  →  FastF1 Q  →  Jolpica /qualifying  →  grid = standings order
race pace:                  FastF1 long runs       →  OpenF1 FP laps  →  quali pace × 1.031 (empirical offset)
team form:                  Jolpica standings      →  season results  →  uniform prior
weather:                    OpenF1 weather         →  Open-Meteo forecast  →  assume dry
```

Each field carries a `source` tag in the output JSON so the UI can show provenance honestly.

### 4.4 Caching

`~/.cache/f1predictor/` — FastF1 native cache + `snapshots/<session_key>/<endpoint>.json`. Every run is offline-reproducible after the first fetch. `--refresh` bypasses.

## 5. Feature Engineering

One row per driver. All pace features in **seconds**, normalised to the session fastest.

| Feature | Definition | Source |
|---|---|---|
| `q_best` | Best qualifying lap across Q1–Q3 | OpenF1 / FastF1 |
| `q_gap` | `q_best − pole_time` | derived |
| `q_segment` | Reached Q3 / Q2 / Q1 | OpenF1 |
| `race_pace` | Median of clean long-run laps, fuel-corrected to 0 kg | FastF1 |
| `pace_gap` | `race_pace − session_best_race_pace` | derived |
| `deg_rate` | OLS slope of lap time vs tyre age per compound (s/lap) | FastF1 |
| `stint_consistency` | Std-dev of clean long-run laps | FastF1 |
| `top_speed` | Max speed trap | OpenF1 `st_speed` / FastF1 |
| `team_form` | Constructor points per race, last 5 rounds | Jolpica |
| `driver_form` | Driver points per race, last 5 rounds | Jolpica |
| `circuit_affinity` | Mean finish position at COTA (career), Laplace-smoothed | Jolpica |
| `dnf_rate` | Season DNF share | Jolpica |
| `grid` | Official or derived grid slot | OpenF1 |
| `is_rookie` | No prior COTA start | Jolpica |

### Fuel correction

```
lap_time_corrected = lap_time_measured + FUEL_EFFECT × fuel_mass_on_board
FUEL_EFFECT = 0.030 s/kg          # standard F1 estimate
fuel_mass(lap) = START_FUEL × (1 − lap/laps_total)
START_FUEL ≈ 100 kg (race) · 60 kg (long run, inferred)
```

### Track evolution correction

COTA grips up ~0.4 s across a session. Each lap is normalised to a common reference using a linear fit of session-best-per-lap against session time.

## 6. Prediction Engine

### 6.1 Monte Carlo race simulation (weight 0.60)

Lap-by-lap, `N = 20 000` races. Each run is independent.

**Per-lap model**

```
t_i(lap) = base_i
         + deg_i × tyre_age
         + fuel(lap) × FUEL_EFFECT
         + dirty_air_i(lap)
         + ε_i          ,  ε ~ N(0, σ_i)
```

- `base_i` — fuel-corrected long-run pace + quali-pace blend `0.65 × long_run + 0.35 × quali`
- `deg_i` — compound-weighted degradation slope, per driver
- `σ_i` — driver-specific lap noise (0.10–0.25 s), from stint consistency
- `dirty_air` — +0.35 s when within 1.2 s of the car ahead and unable to pass

**Overtaking model** (COTA-tuned)

```
if gap < 1.0s and pace_delta > 0.25s/lap:
    P(pass per lap) = clip(0.18 + 1.6 × (pace_delta − 0.25), 0, 0.85)
```
COTA is a medium-difficulty circuit (T12 hairpin after 1.2 km straight, DRS zone 1).

**Stochastic events**

| Event | Rate | Effect |
|---|---|---|
| Safety Car | 0.35 per race | Field bunches to <1.0 s, pit loss reduced 8 s |
| Virtual SC | 0.20 per race | 3 s lap-time delta, no bunching |
| Mechanical DNF | per-driver `dnf_rate × 1.2` | Retires |
| Collision DNF | 0.03 per driver per race | Retires, may trigger SC |
| Pit-stop noise | σ = 0.45 s | Added to stop loss |
| Pit loss | 21.5 s ± 0.9 s | COTA pit lane |

**Strategy solver** — per team, evaluate 1-stop (M→H) vs 2-stop (S→M→M) on expected total time, pick the minimum, add 8% randomness to reflect real-world divergence.

**Outputs per driver** from the 20 000 runs: `P(win)`, `P(podium)`, `P(points)`, `P(top10)`, median finish, 10th–90th percentile finish band, expected gap to winner.

### 6.2 Gradient-boosted classifier (weight 0.40)

- **Corpus:** Jolpica race results 2022-01 → 2026-17 (~110 races, ~2 200 rows)
- **Target:** multiclass finish bucket `{P1, P2, P3, P4-6, P7-10, P11-15, P16+}`
- **Features:** `grid`, `q_gap`, `driver_form`, `team_form`, `circuit_affinity`, `dnf_rate`, `season_round`, `is_2026_regs` (era flag), `team_id`
- **Model:** `HistGradientBoostingClassifier`, 5-fold time-series CV, sample weight `1.0 + 0.8 × is_2026` (new-regulations era weighted up)
- **Output:** class probabilities → marginalise to `P(win)`, `P(podium)`, `P(points)`

### 6.3 Blend & calibration

```
p_final = normalize( 0.60 × p_mc + 0.40 × p_ml )
```

Then temperature-scale (`T ≈ 1.15`) so the favourite's win probability sits in the realistic 25–55% band rather than over-converging. Sanity guards, asserted at build time: `Σ P(win) = 1.00`, `Σ P(podium) = 3.00`, `Σ P(points) = 10.00` (ten scoring positions, not twenty — an earlier draft of this plan had this wrong).

A final guard stops the historical prior from inventing a contender. The first attempt was a hard cap (`2 × P_mc(win) + 0.2%`, excess redistributed), but a cap applied across 22 drivers flattens the entire tail to one number. **Geometric (log-opinion) blending replaced it**: multiplying the two distributions lets a near-zero simulation probability suppress the prior naturally, so no cap is needed and the field keeps a meaningful spread.

$$p_{win} \propto p_{mc}^{0.6} \cdot p_{ml}^{0.4}$$

### 6.4 Explainability

Every driver carries a contribution vector so the UI can show *why*:

```json
"drivers": [{ "code": "ANT", "win_prob": 0.31, "contributions": {
  "quali_pace": +0.42, "race_pace": +0.28, "team_form": +0.19,
  "circuit_affinity": +0.06, "reliability": +0.05 } }]
```

## 8. UI Design Brief

**"APEX — F1 Race Intelligence"**
A single-screen prediction dashboard for one Grand Prix. The user opens it 3 hours before lights out, reads the projected podium in 3 seconds, then drills into *why*.

F1-literate fans and analysts. Tone: **engineering precision, not gaming**. Reference points: F1 official broadcast graphics, FIA timing screens, telemetry HUDs, Bloomberg terminal density. No gradients-on-purple, no neon glow, no cartoon speed lines.

### 8.6 Motion

- Page load: cards fade+rise 8 px, staggered 60 ms. Nothing bounces.
- Bars animate width once. No looping animation.
- Hover on a driver row highlights the same driver in the podium card and scatter (cross-filter). This is the single most important interaction.
- Reduced-motion: all transitions → 0 ms.

### 8.7 Accessibility

- Contrast ≥ 4.5:1 for all text (team colours are *never* text on dark).
- Full keyboard navigation; `:focus-visible` ring `2px --accent-cool`.
- Table uses real `<table>` semantics with `<th scope>`.
- Probability conveyed by number **and** bar, never colour alone.

### 8.8 Responsive

- ≥ 1280: full 12-col layout
- 768–1279: podium and chart stack; table drops `Deg` and `DNF%` columns
- < 768: single column; table becomes cards; hero collapses to race name + confidence

### 8.9 Data binding

The dashboard reads `output/prediction.json` via `fetch()`. **No hardcoded numbers anywhere.** A `?demo=1` flag loads `prediction.sample.json` so the designer can iterate without running Python.

## 11. Validation — actual results

Replayed all 17 completed rounds of 2026. The prior is trained only on 2022–2025, so
every round is genuinely out-of-sample for the ML component; features are rebuilt from
data available before each race.

| Metric | Result | Target | Verdict |
|---|---|---|---|
| MAE of expected finish | **3.60 positions** | < 2.5 | ✗ target was optimistic for a 22-car field |
| Brier score (summed over field) | **0.694** | < 0.08 | — target was mis-specified; see note |
| Actual winner in predicted top 3 | **71%** (12/17) | ≥ 2 of 3 | ✓ |
| Sanity guards | Σwin 1.000 · Σpodium 3.000 · Σpoints 10.000 | exact | ✓ |

> **On the Brier target:** 0.08 is only achievable for a binary forecast. This score sums
> squared error across 22 drivers per race, so its range is 0–2. A *perfectly calibrated*
> model with this confidence profile floors at roughly 0.63, so 0.694 is close to optimal
> for the shape of the distribution it produces. The original 0.08 target was wrong.

Round-by-round MAE ranged 2.21 (Belgium) to 5.55 (Monaco) — street circuits and
safety-car-heavy races are, as expected, the hardest.

### Calibration work

The first backtest scored Brier **0.814** — the model was over-confident on the
favourite. Two remedies were tested:

1. **Temperature scaling** (`T` 1.15 → 1.84): Brier 0.814 → 0.769, but it distorted the
   tail badly (a 3% driver became 10%).
2. **Shrinkage toward uniform** (`a` 0.32): Brier 0.814 → 0.776, but combined with the
   win-probability cap it flattened 16 drivers to an identical 0.2%, destroying the
   spread that makes the output readable.

Neither was adopted as-is. The fix that worked was **geometric (log-opinion) blending**
plus a milder temperature (`T = 1.30`): Brier **0.814 → 0.694**, tail preserved, no cap
needed. A final shrinkage sweep on the tuned model finds `a = 0.08` worth only 0.004
Brier, so it is left off.

## 15. Build Log — what the implementation verified

These are findings from the actual build, superseding the assumptions above.

### 15.1 FastF1 cannot load 2026 data (confirmed)

`livetiming.formula1.com/static/2026/Index.json` returns **HTTP 401**. F1 moved the
timing feed behind authentication, so `Session.load()` raises
`SessionNotAvailableError` and FastF1 yields zero laps for 2026 — and for 2025 as
well in this environment. This was flagged in §12 as *medium likelihood / high
impact*; it materialised.

**Resolution:** OpenF1 became the primary lap/stint/compound source. It supplies
everything the pace model needs — lap durations, sector splits, stint boundaries,
compound names, pit-out flags, speed traps. FastF1 is retained as an optional
enrichment layer (`src/sources/fastf1_source.py`) that activates automatically if
authenticated access appears. Every run records the degradation honestly in
`meta.model.fastf1`.

### 15.2 Jolpica paginates at 100 rows

`limit=1000` is silently clamped to 100. `/{season}/results/1.json` means **round 1**,
not "all results with position 1". Both were fixed: `_all_races()` walks `offset`
and merges by `(season, round)`, and the corpus query uses `/{season}/results.json`.
This took the ML training set from 109 rows to **2 212**.

### 15.3 Raw practice pace is unusable without normalisation

Measured stint slopes ranged from −7.6 to +5.5 s/lap because practice mixes
qualifying simulations with race simulations, and some sessions are partly wet.
Three corrections were necessary:

| Problem | Correction |
|---|---|
| Low-fuel runs contaminate the minimum | Require ≥ 5 timed laps before a stint counts as sustained; discard stints > 6% off the session's fastest sustained run |
| In-laps and traffic inflate the median | Trim laps > 3% off the stint median |
| Fuel loads differ between teams | Compare `long-run median − own qualifying lap`, so common effects cancel |
| Compounds differ | Express every run as MEDIUM-equivalent before ranking |
| Degradation slope is contaminated by fuel burn | Add back `0.030 × 1.79 = 0.054 s/lap`, then keep only the team *ratio* and anchor the level to a circuit prior |

### 15.4 Track position had to be calibrated, not assumed

The first working simulation gave pole position an **8.9%** win rate with all cars
set to identical pace — the field shuffled like there was no cost to overtaking.
Root cause: per-lap noise (σ ≈ 0.2 s) accumulates to ~1.5 s over 56 laps, which
swamps a grid slot's literal 0.35 s spacing. A grid slot is worth far more than
its physical spacing because passing costs time.

**Fix:** `GRID_GAP = 1.6 s` per slot, plus a persistent per-race form offset of only
0.05 s/lap (an earlier 0.14 s/lap compounded to ±7.8 s over a race and destroyed
grid relevance). With identical cars the model now gives pole **33.4%**, against
COTA's historical 4 wins from 13 poles (31%). That is the anchor.

### 15.5 Degradation is a car property

Per-driver degradation estimates were unstable (0.015 to 0.16 s/lap, saturating the
clamp). Tyre wear is dominated by the car, so degradation is now pooled per team,
expressed as a ratio to the field median, and applied to a circuit prior of
0.075 s/lap. Observed spread: 0.049–0.082 s/lap across teams.

### 15.6 Expected finish is conditional on finishing

Including retirements in the mean produced contradictions — a driver with a 23%
DNF rate and a median finish of 1st showed an "expected finish" of 5.9. Expected
finish and the position band are now computed over finishing simulations only;
retirement risk is exposed separately as `dnf_prob`. DNF rates are also shrunk
toward an 8% baseline: Aston Martin genuinely retired 11 of 17 races, but a
17-race sample should not imply a 65% single-race failure probability.

### 15.7 Blend in log space, not arithmetic space

Arithmetic blending (`0.6·MC + 0.4·ML`) let the prior hand a P22 Cadillac a 0.9% win
chance, which then required a hard cap — and a cap applied across 22 drivers flattens
the whole tail to an identical number. The first capped run printed **0.2% for sixteen
drivers in a row**, which is both uninformative and obviously synthetic.

Geometric blending fixes it structurally: `p ∝ p_mc^0.6 · p_ml^0.4`. Where the
simulation says a driver cannot win, the prior is multiplied into irrelevance. No cap,
and the tail keeps a real gradient (0.5%, 0.3%, 0.1%, 0.05%, …). Combined with
`CALIBRATION_T = 1.30`, this also cut the season Brier from 0.814 to **0.694**.

### 15.8 Per-lap noise is not the same as race-time uncertainty

An early version applied a per-race form offset of 0.14 s/lap. Because the offset
persists across all 56 laps, it compounds to ±7.8 s — larger than any realistic pace
advantage, so it randomised the field. Reduced to 0.05 s/lap (±2.8 s), which is the
right order for setup and condition variation.
